# DTM工程管理

楽曲制作(DTM)の作業を「セクションごとのタスク」として管理するローカルWebアプリ。1曲を1プロジェクトとし、複数のプロジェクトを並行して持てる。

- 構成(セクション)は自由に編集できる。歌モノ以外にも使える。
- 曲の種類ごとの「テンプレート」に、セクションの並びと毎回やる作業(ノウハウ)を用意しておき、プロジェクトを作るたびに丸ごとコピーする。テンプレートはプロジェクトと同じ画面で育てる。
- 運用ルールに頼らず、型はツール側の構造で保つ。
- 計画変更(セクションの追加・削除・並べ替え、タスクの移動)を気軽にできる。

## 起動

ビルドは不要。静的サーバーで配信して開く(`file://` では ES Modules が動かない)。

```
python -m http.server 8765      # または npx serve .
```

`http://localhost:8765/` を開くとログイン画面が出る。Supabase の Project URL と公開キーを入れるか、「ログインせずに使う」を選ぶ(その場合、データはそのブラウザの IndexedDB に入る)。

テストは `http://localhost:8765/test.html` を開くか、Node で実行する。

### インストール(PWA)

PWA に対応している。Chrome / Edge ならアドレスバーのインストールボタン、スマホならメニューの「ホーム画面に追加」で、アプリとして独立したウィンドウで開ける。

- 一度開くと、画面のファイル(HTML・CSS・JS と CDN のライブラリ)が Service Worker(`sw.js`)にキャッシュされ、オフラインでも起動できる。
- オフラインで使えるのは、ログインせずに(IndexedDB で)使っているときだけ。Supabase に保存しているときは、起動はできても読み書きできない。
- 自前のファイルはネットワーク優先で読む。つながっていれば常に最新が使われるので、ファイルを変えたときにキャッシュの名前を変える必要はない。
- キャッシュ(Cache Storage)が使えないとき(壊れている、容量の上限など)も、ネットワークから取れるものはそのまま返す。キャッシュの失敗で画面が開けなくなると、Service Worker を消すまで直らないため。以前の sw.js でこの状態になっていた端末も、一度開き直せば新しい sw.js に入れ替わって直る。- Service Worker は `localhost` か HTTPS でしか動かない(GitHub Pages は HTTPS なので動く)。

```
node -e "import('./test/domain.test.js').then(m => m.report()).then(ok => process.exit(ok ? 0 : 1))"
```

## 保存先とログイン

- **擬似ログイン**:ログイン画面で Supabase の Project URL と公開キー(anon / publishable key)を入力する。接続を確かめてから、入力値をそのブラウザの localStorage に保存する(`js/session.js`)。Supabase Auth によるユーザー認証はしていない。
- **1つの Supabase プロジェクトを1人で使う前提**。Project URL と公開キーを知っていれば全データを読み書きできる。だから公開キーはリポジトリに入れず、人にも渡さない。
- **テーブルの用意**:`supabase/schema.sql` を Supabase の SQL Editor に貼り付けて実行する(初回だけ。何度実行してもよい)。テーブルは、レコードを jsonb のまま入れる `records` と、`app_meta` の2つだけ。アプリ側で項目を足したり変えたりしても、実行し直す必要はない。空の状態から作り直したいときは、先に `supabase/drop.sql` を実行する(データはすべて消える)。
- **データの形の変換は起動時に自動で行う**(保存先が Supabase でも IndexedDB でも同じ)。詳しくは「技術方針」。
- **ログインせずに使う**こともできる。その場合の保存先はそのブラウザの IndexedDB。Supabase 側とは別のデータで、自動では移らない(移すには、エクスポートしてからログイン後にインポートする)。
- **使い分け**:実際の作業の記録は Supabase に置く。Supabase の実データに触らずに試したいとき(画面の動作確認など)は、ログインせずに(IndexedDB で)使う。IndexedDB のデータは「そのブラウザの、そのURL(ポート番号を含む)」にしかない。
- **ログアウト**は設定画面から。localStorage の接続情報を消すだけで、Supabase 上のデータは残る。
- Supabase に保存しているときは、操作のたびに通信する(読む→保存→読み直す)。オフラインでは使えない(IndexedDB ならオフラインでも使える。「インストール(PWA)」を参照)。
- **通信に時間が掛かったとき**:操作(`actions.js` の各操作とインポート)が5秒を過ぎても終わらなければ、画面下に「処理中です…」を出し、終わるまで出し続ける(いくつも待っていれば、すべて終わるまで)。3秒以上かかって正常に終わったら「保存が完了しました」のトーストを出す(続けて「元に戻す」などのトーストが出る操作では、そちらに置き換わる)。時間は操作を呼んだときから測る(前の操作の終わりを待っている間も含む)。失敗したときはエラーのトーストだけを出す。保存先が IndexedDB でも同じ(ふつうは速いので出ない)。`js/ui/components/slowNotice.js`
- **Supabase に届かないとき**:操作はすべて失敗し、そのたびにトーストで知らせる(「読み込みも保存もできませんでした」)。成功したように見せたまま捨てることはしない。
   - 端末がオフラインの間は、ヘッダーの下に「オフラインです…変更は保存されません」のお知らせを出し続ける(`js/ui/connectionBanner.js`)。オンラインに戻るとお知らせを消し、保存先から読み直して描き直す。
   - 画面を先に動かすドラッグ(ボードのタスク・セクション、アレンジ)は、保存に失敗したら保存済みの並びに描き直す。
   - タスク詳細の入力は、保存に失敗しても欄に打った内容を残し、次に欄を離れたときや閉じるときに保存し直す(閉じるときにも失敗すると、その内容は残らない)。
   - 起動時に届かなければ、「データを読み込めませんでした」と再試行のボタンを出す。
   - オフラインの間の変更を貯めておいて後で送る仕組みはない(「これから」を参照)。

## 仕様

### 決めたこと

| 項目 | 決定 |
|---|---|
| 工程軸(作曲→編曲→ミックス…) | 持たない。マトリクス表示もしない |
| 動線(作業順) | レーン内の並び順で表現する。初期順はテンプレートでの並び順で、以後はドラッグで入れ替える。タスク間の依存関係は持たない |
| テンプレート | 曲の種類(歌モノ、インスト…)ごとに作る。中身は「ステータスのないプロジェクト」で、「全体」レーンとセクションのレーン、その中のタスクを持つ。プロジェクトと同じボードで編集する |
| プロジェクトとテンプレート | プロジェクトは、テンプレートを丸ごとコピーして作る。作成元は覚えない(テンプレートを編集・削除しても、作成済みのプロジェクトには影響しない) |
| セクション種別 | 持たない(廃止)。「サビ」「サビ2」「サビ3」は、テンプレートでもプロジェクトでも別々のレーン |
| タスクの属性 | タイトル / ステータス(未着手・作業中・完了) / 開始日・終了日 / リファレンス / メモ。見積もり時間は持たない |
| リファレンス | 参考にする楽曲の曲名を、タスクごとに自由入力で付ける(複数可)。曲全体のものは「全体」レーンのタスクに付ける。曲名を管理する画面は作らず、同じプロジェクトのタスクに付いている曲名を候補に出して表記揺れを防ぐだけ。曲ごとのものなので、テンプレートには持たせない。ボードのタスク行には出さない。プロジェクトで使っている曲名は、ボードのツールバーのボタン(音符)から開くダイアログで一覧できる(見るだけ。どのタスクに付いているかは出さない) |
| タスクの開始日・終了日 | 実績(着手した日・終わった日)を記録する。予定は入れない。ステータスを変えたときに自動で入り、タスク詳細で修正できる。ボードのタスク一覧には出さない。テンプレートには持たせない |
| ガントチャート | プロジェクトのボードの下に出す、作業の記録(予定ではない)。着手済みで開始日のあるタスクを、セクションをまたいで開始日の早い順に並べる。表示のみ。テンプレートとスマホ幅では出さない |
| 締切 | プロジェクトごとに任意で1つ(日付のみ)。一覧のカードとボードに残り日数を出す。3日以内は強調、過ぎたら超過日数を赤で出す。全タスク完了なら日付だけ |
| 「全体」レーン | すべてのプロジェクトとテンプレートに必ず1本ある。名前変更・複製・削除・並べ替えはできない |
| アレンジ | プロジェクトごとの、DAW のアレンジ画面のような別ページ(ボードとタブで切り替える)。トラックを縦に並べ、クリップ(名前と詳細)を1小節単位で置く。上端にはセクションマーカーを置く。マーカーはボードのセクションを指す。テンプレートには持たせず、コピーもしない |
| MIDI クリップ | アレンジのクリップはノートを持てる(ピアノロールで編集する)。最低限の下書き用で、拍子は 4/4 固定、テンポはプロジェクトに1つ(BPM。テンポチェンジなし)。トラックは1本につき1音色(General MIDI)と音量・パン、ミュート・ソロだけを持ち、CC やオートメーションは持たない。再生はブラウザの中で、端末ごとに選んだ SoundFont / DLS を鳴らす(spessasynth_lib)。クリップ単位・アレンジ全体で .mid に書き出せる(DAW へは、そのファイルで渡す。ブラウザから DAW へのドラッグは FL Studio が受け取らなかったのでやめた) |
| アレンジとボード | クリップは、属するセクションのレーンに「トラック名: クリップ名」のタスク(連動タスク)として出る。内部では Task に `clipId` を持たせる。名前・詳細・位置はクリップ、ステータス・日付・リファレンス・レーン内の並び順はタスクが持つ。クリップはセクションマーカーの範囲の外には新しく置けない |
| 色 | 選ばせない。プロジェクトごとに、セクションの並び順で固定パレットの色を先頭から1色ずつ割り振る(名前は見ない。「サビ」と「サビ2」も別の色)。パレットは18色で、系統の違う9色(Tailwind の500)と、それぞれを明るくした9色(同300) |
| タスクの出自 | 持たない。テンプレートからコピーしたタスクも、プロジェクトで足したタスクも区別しない |

### 画面

| ルート | 画面 | 内容 |
|---|---|---|
| `#/` | プロジェクト一覧 | カード(進捗、締切、最終更新。最終更新の新しい順)。カードの上に締切パネルを出す(締切のある未完了のプロジェクトを締切の近い順に、「リスト」か「タイムライン」で見せる。どちらを出すかはタブで選び、ブラウザに覚える。リストは日付・曜日・タイトル・残り日数・作業日の列を全行で同じ幅に揃え、日付と数字は右寄せにする。リストの締切日は曜日を併記する(「10/16(金)」。年は出さない。締切の近い順に並ぶので、12月のあとの1月は来年と分かる)。リストでは「あと◯日」に、そのうちの土日の日数を「作業日」として併記する(土日に作業する場合の目安。「あと9日(4作業日)」。数える範囲は「あと◯日」と同じで、今日は含めず締切日は含める。今日が締切のときと超過のときは出さない)。全タスク完了のプロジェクトと締切なしは出さない。出すものがなければパネルごと出さない)。新規作成はタイトル・締切・テンプレート・メモを入れる(締切とメモは任意。タイトルは空欄でもよく、そのときは「無題のプロジェクト」になる。テンプレートの初期値は「なし」で、テンプレートのボードの「このテンプレートでプロジェクトを作成」からだけ、そのテンプレートが選ばれた状態で開く) |
| `#/p/:id` | ボード | ツールバーのタブで「ボード」と「アレンジ」を切り替える。「全体」レーンを左端に固定し、セクションのレーンを横に並べる。上部にセクション一覧(チップ)があり、構成を俯瞰でき、押すとそのレーンへジャンプする。着手したタスクがあれば、下にガントチャートが出る。スマホではレーンを縦に積む(ガントチャートは出さない) |
| `#/p/:id/arrange` | アレンジ | 上端に小節番号のルーラーとセクションマーカーの段、その下にトラックを縦に並べる。縦横にスクロールし、トラック名の列は左に、ルーラーとマーカーは上に残る |
| `#/templates` | テンプレート一覧 | カード(名前、メモ、セクションとタスクの数)。新規作成、名前とメモの編集、複製、削除 |
| `#/t/:id` | テンプレートの編集 | プロジェクトと同じボード。ステータスまわりだけ出さない |
| `#/settings` | 設定 | UIテーマ(システム / ライト / ダーク)、音源(SoundFont / DLS のファイル。このブラウザだけ)、保存先の表示とログアウト、JSONのエクスポート/インポート |

ボードでできること(★はプロジェクトだけ。ほかはテンプレートの編集でも同じ):

- ★ステータス切替(丸をクリックで 未着手 → 作業中 → 完了 と循環。保存を待っている間は丸が回る)、★「未完了のみ」フィルタ
- レーン末尾のクイック入力(Enterで連続追加)
- タスクのドラッグ(レーン内の並べ替え、レーン間の移動)、セクションのドラッグ(ヘッダーを掴む)
- セクションの追加(レーン間の「+」または末尾のボタン)。空のセクションか、テンプレートのセクションをタスクごと取り込むかを選ぶ
- セクションの名前変更、複製、折りたたみ、削除
- タスク詳細(PCは右ドロワー、スマホはボトムシート)で編集・削除。★着手後は開始日を、完了後は終了日も、ここで修正できる
- ★タスク詳細でリファレンス(曲名)を付ける・外す。ツールバーの音符のボタンで、プロジェクトのリファレンスの一覧(名前順。見るだけ)を出す
- レーンとタスクの削除は、トーストから直前の1回を元に戻せる
- ★プロジェクトのメニューから「テンプレートとして保存」
- テンプレートのメニューから「複製」「このテンプレートでプロジェクトを作成」

アレンジでできること:

- トラック名の列の幅は、いちばん長い名前に合わせる(短ければ 192px のまま。長くても全角10文字が入る幅までで、それより長い名前は … で切る)。スマホ幅では広げない
- トラックの追加(下端の「トラックを追加」。名前が空なら「トラック」)、名前変更、削除(クリップと、その連動タスクも消える。確認ダイアログに件数が出る。トーストから元に戻せる)、並べ替え(見出しを掴む)
- クリップの作成:トラックの空いているところをドラッグすると、その範囲で作る。ダブルクリックなら1小節。作るとクリップ詳細が開き、すぐ名前を打てる。セクションマーカーの範囲に1小節も重ならない位置には作れない(マーカーが1つもなければ、先に置くよう知らせる)
- クリップの移動(本体をドラッグ。上下に動かすと別のトラックへ)、伸縮(左右の端をドラッグ)。動かさずに離すか、Enter で詳細が開く。作成と同じく、範囲の外へは動かせない・伸ばせない
- クリップ詳細(タスク詳細と同じドロワー):名前、詳細、ボードのどのセクションに出ているか、連動タスクのステータス(タスク詳細と同じ3つのボタン。無所属の間は出さない)、複製、削除(トーストから元に戻せる)。アレンジ画面の右端に最前面で重ねて出し、下の画面(ツールバーや小節)は詰めない(隠れた小節は閉じれば見える)
- クリップの複数選択:Ctrl+ドラッグで囲んだクリップを選ぶ(トラックをまたげる。Ctrl+Shift+ドラッグで選択に足す)。Ctrl+クリックで1つずつ選択を切り替え、Ctrl+A で全部を選ぶ。選んだものは点線の枠で出る。選んだものの1つを掴んでドラッグすると、まとめて横に動く(上下には動かない。1つでも重なる位置や範囲の外になるなら、置き先が赤くなり、離しても動かない)。←→ でまとめて1小節ずつ動かす(置けなければ動かない)。Esc か、空いているところや選んでいないクリップを押すと選択を外す。選んだものを動かさずに離すと、選択を外してそのクリップの詳細を開く
- クリップの複製:クリップ詳細の「クリップを複製」を押すと、同じ長さの置き先がポインタに付いて動く(トラックをまたげる)。押したところに、名前・詳細・ノートをコピーした別のクリップを作り、その詳細を開く。元のクリップとはつながらない(フォーク。連動タスクも新しく未着手で作られる)。重なる位置やセクションマーカーの範囲の外では置き先が赤くなり、押しても置かない。Esc か右クリック、案内の「取り消し」でやめる
- セクションマーカー:マーカーの段の小節を押して、ボードのセクションを選ぶ。旗を押すと別のセクションへの変更か削除、横にドラッグで移動
- スケール(転調):セクションの段の下に「スケール」の段がある。小節を押すと、キー(C〜B)とメジャー / マイナー(自然的短音階)を選んで、そこで転調する(次の転調まで続く)。旗を押すとスケールの変更か削除(元に戻せる)、横にドラッグで移動。1小節目の旗は曲の頭のスケールなので、動かせず消せない(変更はできる)。新しいプロジェクトは1小節目から C メジャー。教会旋法などは扱わない。ピアノロールの塗り分けだけに使い、再生や書き出しには関わらない
- トラックの音:トラック名の下の音色名(またはメニューの「音色・音量・パン」)から、General MIDI の音色、ドラム(10ch で鳴らす)、音量、パンを変える。新しいトラックはピアノ・音量100・パン中央
   - ダイアログの音色は、絞り込みの欄と、系統(ピアノ、ギター、ストリングス…の16系統)ごとの見出しの下に音色を数列に並べた一覧から選ぶ。絞り込みは番号・音色名・系統名の部分一致(空白で区切ると、すべてを含むもの。全角・半角、大文字・小文字は区別しない)。欄で Enter を押すと、絞り込んだ先頭の音色を選ぶ。音色のダブルクリックは、選んでそのまま保存
   - 音色名の右に、音量とパンのつまみがある。上下にドラッグで変え(Shift を押しながらだと細かく)、ダブルクリックで既定値(音量100・パン中央)に戻す。フォーカスがあれば ↑↓←→ でも1ずつ(Shift で10ずつ)動く。ホイールでは動かない(縦スクロールとぶつかるため)。動かしている間もすぐ音に効き、離したら保存する。値はつまみの title(「パン: R10」など)に出る
   - ダイアログの音量とパンは、横スライダーと数値の欄(実際の値 0〜127。パンは 64 が中央)。どちらで変えても、もう一方に映る。範囲の外の値は端に寄せる。スライダーのダブルクリックで既定値(音量100・パン中央)に戻す。保存を押したときに効く
   - ミュート(`volume-x`)とソロ(`headphones`)のボタンがトラック名の横にある。ソロのトラックがあればソロのものだけを、なければミュートしていないものを鳴らす(ソロはミュートより強い)。ON のボタンは塗りつぶす(ミュートはオレンジ、ソロは青)。押したあとボタンにフォーカスが残っていても、スペースキーは再生・停止になる(ボタンの切り替えは Enter)。鳴らないトラックはクリップを薄く出す。トラックに保存する。書き出し(.mid)には効かない(全トラックを出す)
- ピアノロール:クリップをダブルクリック(またはクリップ詳細の「ピアノロールで編集」)で、画面の下に開く。開いている間は、クリップを押すとそのクリップに切り替わる。
   - 空いているところを押すとノートを置き、そのままドラッグで動かせる。ノートを掴むと移動(上下で音の高さ)、右端を掴むと長さを変える。右クリックで消す(押したままなぞると続けて消す)。ノートはクリップの範囲(左端〜右端)からはみ出すようには動かせない(ドラッグでも矢印キーでも。置くノートや長さの変更も、右端で止まる。もともとはみ出しているノートは、それ以上外へ動かさない)。Shift+クリックで複数選択、Ctrl+ドラッグで囲んだノートを選択(Ctrl+Shift+ドラッグで選択に足す)、Ctrl+A で全選択。選択中のノートはまとめて、Delete で削除、↑↓ で半音(Shift か Ctrl で1オクターブ)、←→ でグリッド1つ分(Shift か Ctrl で1小節)動かす。Esc で選択を外し、選択がなければ閉じる
   - コピー・貼り付け:選んだノートを Ctrl+C でコピーし、Ctrl+V で貼り付ける。貼り付ける位置は、再生を始める位置(赤い印)。印がクリップの外なら、クリップの頭。コピーしたノートの並び(いちばん早いノートからの位置と高さ)をそのまま置き、貼り付けたノートを選んだ状態にする。クリップの右端より後ろで始まるノートは貼らず(数を知らせる)、右端をまたぐノートは右端で切る。コピーはクリップや画面を切り替えても残る(ページを読み込み直すと消える。OS のクリップボードは使わない)。再生中は貼り付けできない(コピーはできる)
   - 置くノートの長さは、最後に触ったノートの長さ。グリッドは 1/4〜1/32 と、それぞれの3連、なし から選ぶ(ブラウザに覚える)。いちばん細い縦線はグリッドの細かさに合わせる(「なし」なら 1/16)。Alt を押しながらだとグリッドに合わせない。ベロシティは 100 固定
   - 鍵盤を押すか、ノートを置いたり動かしたりすると、その音を短く鳴らす(音源を読み込み済みのときだけ。読み込み前なら、読み込みを始めるだけで鳴らさない)。鍵盤の表記は 60 = C4
   - グリッドの行は、鍵盤の白黒ではなくスケール(アレンジ画面の「スケール」の段)で塗り分ける(スケールの外の音を暗く、主音を少し色付きに。鍵盤は実際の白黒のまま)。クリップの途中で転調していれば、転調の位置(縦の線)から塗り分けを変える。ヘッダーには、クリップに掛かるスケールを「C メジャー → A マイナー」のように出す。表示だけに使い、ノートの置き場所は制限しない
   - 同じ高さ・同じ位置で始まるノートが重なっていると(長さが違っても)、どちらも赤く出す。重なりはそのまま保存するので、気付いたら片方を消す。動かして重ねても、選択は動かしたノートだけに残る
   - 元に戻す機能はない
- 再生:ツールバーの再生ボタンかスペースキーで、ルーラーで選んだ小節(赤い印)から全体を再生・停止する。ルーラーを押すと開始位置が変わる(再生中ならそこから鳴らし直す)。ピアノロールの上端の小節番号の段を押しても変わる(こちらは拍単位。印は両方のルーラーに出る。ピアノロールから再生中なら、編集中のトラックはミュートしていても鳴らし続ける)。ピアノロールの再生ボタンは、そのクリップの頭から全体を鳴らす。このとき、そのクリップのトラックだけはミュートしていても(ほかのトラックがソロでも)鳴らす。再生中は赤い線が動き、画面の外へ出そうなら横にスクロールする。再生中にノート・音色・音量・パン・ミュート・ソロを変えると、止めずにその先から差し替える(伸びている音は途切れない。消したノートやミュートしたトラックの音は、すぐ止める)。BPM を変えたときだけ、いまの位置から鳴らし直す。全トラックをミュートしても、曲の終わりまで再生位置は進む
- BPM はツールバーで変える(20〜300)。音源は設定画面で選ぶ(ツールバーにはファイル名だけを出す)
- .mid:ツールバーのボタンでアレンジ全体を、クリップ詳細とピアノロールのボタンでクリップ1つ分を書き出す

### 知っておく挙動

- **テンプレートとプロジェクトは切り離されている**。プロジェクトを作るときにテンプレートのセクションとタスクを丸ごとコピーし、作成元は覚えない。だから、テンプレートを編集・削除しても、作成済みのプロジェクトには何も起きない。
- **テンプレートの編集**は、プロジェクトと同じボードで行う。ステータスの丸、進捗、締切、「未完了のみ」、タスクの開始日・終了日は出ない(テンプレートはステータスも日付も使わない)。ツールバーに「テンプレート」の印が出る。
- **タスクの開始日・終了日**は実績で、ステータスを変えたときに自動で入る。作業中にすると、開始日が空なら今日が入る。完了にすると終了日に今日が入る(未着手から直接なら開始日も今日)。完了を取り消すと終了日が消え、未着手に戻すと開始日も消える。丸のクリックは 未着手 → 作業中 → 完了 → 未着手 と循環するので、誤って完了にしたものを作業中へ戻すと、開始日は今日に置き換わる(必要なら手で直す)。
- **日付の修正**はタスク詳細で行う。未着手では日付の欄が出ず、作業中は開始日、完了は開始日と終了日が出る。終了日を開始日より前にはできない(保存せずに元の値へ戻す)。欄を空にすることはできる。
- **ガントチャート**に出るのは、作業中か完了で、開始日のあるタスク。1件もなければ領域ごと出ず、ボードが全高になる。高さは行数に合わせ、多いときは画面の半分までで、中でスクロールする。上端のつまみをドラッグすると高さを変えられる(上下の矢印キーでも動く。ダブルクリックで元に戻る)。画面の半分より高くはならない。決めた高さは、そのブラウザの localStorage に覚える(全プロジェクト共通)。バーは開始日から終了日まで。色はステータスで塗り分け、作業中はアクセント色(青)、完了は灰色(セクションの色は使わない。セクションは行の左に名前で出す)。作業中のものは今日まで伸ばし、右端をぼかす。終了日を空にした完了タスクは、完了した日で止める。1日が1列の固定幅で、横にスクロールする(出た最初は今日が見える位置に合わせる)。今日の列と、締切の日(列の右端に線)に印が付く。範囲は、いちばん早い開始日の3日前から、今日・締切・いちばん遅い終わりのうち最も遅い日の3日後まで。「未完了のみ」は効かない(記録なので、完了した行も残す)。まずはボードとの上下分割で作ってある。不便なら、タブなどでタスク一覧と切り替える形に変える。
- **リファレンス**は、タスク詳細の入力欄に曲名を打って Enter で足し、チップの × で外す。打っている間は、同じプロジェクトのタスクに付いている曲名から、合うものを候補に出す(よく使っている順。前方一致を先に、部分一致を後に。そのタスクに付いているものは出さない)。↑↓ で選んで Enter か、クリックで決める。入力が空でも ↓ で候補を出せる。全角・半角、大文字・小文字、空白、記号の違いしかない曲名は同じ曲とみなし、既にある表記に揃えて足す(「ｌｅｍｏｎ」→「Lemon」)。打ちかけのまま欄を離れたり閉じたりしても、その曲名は足される。日本語入力の変換を確定する Enter では足さない。
- **リファレンスのコピー**:プロジェクトの中でのセクションの複製では引き継ぐ。テンプレートとして保存、テンプレートからの作成、セクションの取り込みでは引き継がない(曲ごとのものなので)。テンプレートのタスク詳細には欄が出ない。
- **日付はコピーに引き継がない**。テンプレートとして保存、テンプレートからの作成、セクションの取り込み、セクションの複製のどれでも、コピー先のタスクは未着手・日付なしになる。
- **ノウハウの育て方**は2つ。テンプレートを直接編集するか、うまくいった曲を「テンプレートとして保存」する。プロジェクトのタスクを1件ずつテンプレートに送る機能(以前の「定番に追加」)はない。
- **テンプレートとして保存**は、プロジェクトのセクションとタスクを丸ごとコピーして新しいテンプレートを作る(メモは引き継ぎ、ステータスと開始日・終了日は引き継がない)。元のプロジェクトは変わらない。
- **セクションの取り込み**は、テンプレートのセクションをタスクごとコピーする。どのテンプレートからでも取り込める(歌モノの曲に、クラブ用テンプレートの「ドロップ」を入れる、など)。取り込み元とのつながりは残らない。名前が重なったら番号が付く。
- **同じ内容のセクション**(サビ、サビ2、サビ3)は、テンプレートの中でも別々のレーンとして持つ。まとめて変えたいときは、1本を直してから残りを消し、「複製」で作り直す。
- **セクションの色**は保存していない。表示のたびに、並び順の先頭から1本ずつパレットの色を割り振る。名前は見ないので「サビ」と「サビ2」も別の色になり、名前を変えても色は変わらない。セクションを並べ替えると色も入れ替わる(赤のAメロ・青のBメロを入れ替えると、Bメロが赤、Aメロが青になる)。19本目からはパレットの先頭に戻る。
- **連動タスク**:クリップは、ボードの「トラック名: クリップ名」のタスクとして出る(名前が空なら「(無題)」)。入るレーンは、セクションマーカーの区間と重なる小節数がいちばん多いセクション。同じセクションをマーカーで何度か使っていれば合計し、同数なら先(左)に出てくるセクション。ボードでは印(Lucide の `audio-lines`)と小節の範囲が付く。
   - 新しく作るとレーンの末尾に入る。セクションが変わったときも、移った先の末尾に入る。レーンの中では並べ替えられるが、別のレーンへはドラッグできない(セクションはアレンジで決まる)。
   - タスク詳細では、「トラック名:」は固定で、クリップ名と詳細(メモ欄)を直す(クリップのものが変わる)。ステータス・日付・リファレンスはふつうのタスクと同じ。削除は「クリップごと削除」(クリップが残っていると、また作られるため)。
   - トラック名・クリップ名・詳細を変えると、タイトルとメモも変わる。
   - **無所属**:マーカーを動かしたり消したりして、どの区間にも重ならなくなったクリップは、その場に残り(点線の枠で出る)、連動タスクはボードにも進捗・ガントチャート・締切パネルの「全タスク完了」にも出なくなる。ただし内部では消さずに持っていて、また区間に入れば、ステータス・日付・リファレンスごと戻る。
   - **削除**:ボードでセクションを消すと、そのレーンの連動タスクも消える(確認ダイアログに件数が出る。元に戻せば状態ごと戻る)。区間にあったクリップは、ほかの区間に入らなければ無所属になり、また区間に入ると未着手のタスクとして作られる。トラックやクリップを消すと、その連動タスクも消える(元に戻せば状態ごと戻る)。
   - 「テンプレートとして保存」と「セクションの複製」では、連動タスクはコピーしない。
   - 連動タスクを揃える処理(`syncClipTasks`)は、アレンジの操作とセクションの削除・取り消しのたびに走る。何度走っても同じ結果になるので、途中で保存に失敗しても次の操作で揃う。Supabase では、そのぶん1操作の通信が増える。
- **アレンジのクリップ**は、同じトラックの中では重ならない。重なる位置に作ろうとしたり、動かしたり伸ばしたりすると、置き先が赤くなり、離しても何も変わらない(元の位置に残る)。別のトラックなら同じ小節に置ける。名前は空でもよく、そのときは「(無題)」と出る。色は連動タスクのステータスに合わせる(ボードのタスクと同じ配色。未着手は青、作業中はオレンジ、完了は緑。無所属の間は点線のまま)。
- **アレンジの小節数**は自動で決まる。いちばん後ろのクリップかマーカーの8小節先までを4小節単位に切り上げて出し、最低32小節。右の余白に置けば、次の表示でさらに伸びる。1小節の幅は固定(テンポを変えても変わらない)。
- **ノートの位置**はクリップの先頭からの相対で持つ。クリップを動かすと(別のトラックへも)ノートも付いていく。左端で伸縮したときは、ノートを曲の中の同じ位置に残す。縮めてクリップの範囲の外(前後)に出たノートは消さずに持ち、鳴らさず、書き出しにも入れない(ピアノロールでは薄く出る。伸ばし直せば戻る)。範囲の終わりをまたぐノートは、終わりで切って鳴らす。
- **再生の音源**:設定画面で選んだ SoundFont(.sf2 / .sf3)か DLS(.dls)を、ブラウザの中(spessasynth_lib の AudioWorklet)で鳴らす。ファイルはそのブラウザの IndexedDB(`dtm-proj-soundfont`。プロジェクトのデータとは別)に入れ、エクスポートには含めない。端末・ブラウザごとに1回選ぶ。
   - Windows なら `C:\Windows\System32\drivers\gm.dls`(Microsoft GS Wavetable Synth と同じ音色。FL Studio の Fruity LSD もこれを読む)を選ぶのが手軽。ブラウザは決まった場所のファイルを自分では読めないので、自動では使えない。設定画面にパス(コピーのボタン付き)を出し、ファイルを選ぶ画面の「ファイル名」欄に貼り付けて開くよう案内する。Windows 以外では案内を出さず、空のまま選んでもらう。
   - 外部の MIDI 音源(Web MIDI)は使わない。Chrome / Edge / Firefox は MSGS を Web MIDI から除外していて鳴らせないため、ブラウザ内の音源に切り替えた。
   - 音源の読み込み(gm.dls は 3MB、GeneralUser GS は 30MB ほど)はアレンジ画面を開いたときに裏で始め、ページを開いている間は使い回す。選ばれていないときに再生を押すと、「設定を開く」のトーストを出す。ツールバーには音源のファイル名(未設定なら「音源を設定」)を出す。
   - 読めないファイルを選ぶと、エラーを出して保存しない(前の音源も消える)。
   - spessasynth_lib は CDN のファイルなので、Service Worker がキャッシュする。一度鳴らせば、オフラインでも鳴る。
- **再生のしかた**:チャンネルはトラックの並び順に 1ch から割り振り(10ch はドラムだけ)、16本目からは使い回す。途中から再生したときは、開始位置より前で始まる音は鳴らさない。
- **.mid の形**:フォーマット1。1本目がテンポと拍子、2本目以降がトラック(名前・音色・音量・パン・ノート)。クリップ1つ分なら、クリップの頭が1小節目。

- **セクションマーカー**はボードのセクション(レーン)を指していて、名前と色はレーンのものを出す(ボードで名前を変えたり並べ替えたりすると、マーカーの表示も変わる)。マーカーの小節から次のマーカーの手前までがそのセクションで、最後のマーカーは右端まで続く。同じ小節には1つだけ。同じセクションを何度使ってもよい。「全体」レーンは選べない。境目はトラックの上にも点線で出る。
- **セクションを削除すると、それを指すマーカーも消える**(確認ダイアログに件数が出る)。セクションの削除を元に戻すと、マーカーも戻る(その間に同じ小節へ別のマーカーを置いていたら、そちらを残す)。
- **アレンジはプロジェクトだけ**が持つ。テンプレートにはタブが出ず、テンプレートからの作成・「テンプレートとして保存」・セクションの取り込みや複製でも、アレンジはコピーしない。
- **「プロジェクト」タブ**は、閲覧中のプロジェクトがあればその画面(ボードかアレンジの、最後に開いていた方)に戻る(テンプレートや設定を見たあとで戻れる)。プロジェクト一覧へは、左上のタイトルかボードの「←」で行く。一覧を開くと「閲覧中」は解除される。
- **インポート**は既存データをすべて置き換える(マージしない)。Supabase では、先にファイルの中身を上書きで入れてから、ファイルにない行を消す。1つのトランザクションではないので、途中で失敗したら同じファイルをもう一度インポートする(失敗しても、行が消えすぎることはない)。エクスポートには、プロジェクトとテンプレートの両方が入る。
- **削除の連鎖**(プロジェクト → レーン・タスク・アレンジ、レーン → タスク・マーカー、トラック → クリップ)は、アプリ側で行う(データベースの外部キーには頼らない)。子を先に消し、親を最後に消すので、途中で失敗しても、もう一度消せば揃う。
- **初期データ**のテンプレートは「歌モノ」と「インスト」の2つ。入るのは、保存先ごとに最初の1回だけ。入れ直す機能はない(消したものを戻したいときは、作り直す)。
- **以前のデータは引き継がない**。テンプレートの持ち方を変えたときに保存の形も変えたので、それより前の IndexedDB のデータは、開いたときに消えて初期データから始まる。前のエクスポートJSON(`schemaVersion` 3 以下)もインポートできない。`schemaVersion` 4 のJSON(タスクに開始日・終了日がない)は、日付なしとしてインポートできる。

## 技術方針

- 素の HTML / CSS / JavaScript(ES Modules)。ビルドステップなし。そのまま GitHub Pages に置ける。
- 外部依存は CDN から読む3つだけ。**SortableJS**(ドラッグ&ドロップ)、**Lucide**(アイコン)、**spessasynth_lib**(SoundFont / DLS の再生。版を固定し、使うときに動的に読む)。SoundFont のファイルはリポジトリに入れない(端末ごとに設定画面で選ぶ)。
- 保存先は Supabase(REST API を `fetch` で直接呼ぶ。SDK は使わない)か、IndexedDB。保存処理は repository 層で抽象化してあり、UIとドメインロジックはどちらに保存しているかを知らない。
- 保存先ごとの実装は「文書ストア」(`DocumentStore`:レコードを JSON のまま、コレクション単位で読む・書く・1項目の一致で絞って消す)だけを持つ。repository の各メソッド、削除の連鎖、エクスポート/インポート、スキーマの変換は、その上に `js/store/repository.js` の `createRepository` で1回だけ組み立てる。
- Supabase では、全レコードを1つのテーブル(`records`)に入れ、項目は `data` 列(jsonb)にそのまま持つ。列に出すのはコレクション名・id・プロジェクトの id だけ。レーンやトラックでの絞り込みは `data->>laneId` のように jsonb の項目で行う。
- ルーティングはハッシュ方式。
- PWA:`manifest.webmanifest` と `sw.js`(登録は `js/pwa.js`)。Service Worker は、同じオリジンのファイルをネットワーク優先、CDN のファイル(URL にバージョンが入っている)をキャッシュ優先で返し、Supabase への通信には関わらない。最初に開いたときの読み込みは Service Worker を通らないので、登録後に画面が読み込み済みのファイルの URL を渡してキャッシュさせる(初回からオフラインで開けるように)。パスはすべて相対にしてあるので、GitHub Pages のサブパスでも動く。
- IDは `crypto.randomUUID()`(初期データだけは固定ID)。
- 並び順は小数の `order`(fractional indexing)。間に入れるときは前後の中間値を使い、他の行を書き換えない。精度が尽きたときだけ全体を振り直す。
- 全レコードに `createdAt` と `updatedAt`。エクスポートデータには `schemaVersion`(現在 10)。`migrate` は 4 より前のデータを読み込まない(変換を用意していない)。4 のデータは、タスクの開始日・終了日を「なし」で補って読み込む。4・5 のデータは、アレンジ(トラック・クリップ・マーカー)なしとして読み込む。6 以前のデータは、タスクに `clipId: null` を補い、セクションに入っているクリップに連動タスクを作って読み込む。7 以前のデータは、プロジェクトに BPM 120、トラックにピアノ・音量100・パン中央、クリップにノートなしを補って読み込む。8 以前のデータは、プロジェクトに1小節目から C メジャーのスケールを補って読み込む。9 のデータ(スケールを1つだけ持っていた `scale`)は、それを1小節目のスケールにして読み込む。
- **保存先のスキーマバージョン**:保存先にも、データ全体で1つの `schemaVersion` を meta に記録する(記録がなければ 6 とみなす。ただし初期データも入っていない、初めて使う保存先は、変換せずに現在のバージョンを記録する)。起動時に `upgradeStorage` がアプリのバージョンと比べる。
   - 保存先が古い:変換前の全データを meta の `backup:v{旧バージョン}:{日時}` に残してから、`migrate` で変換して保存し直し、バージョンを上げる。途中で失敗したらバージョンは上がらないので、次の起動でやり直される。
   - 保存先が新しい(別の端末やタブで新しいアプリが変換した):古い形で書き込むと壊れるので、「再読み込みしてください」を出して止める。開いたままのタブに戻ってきたとき(`visibilitychange`)にも確かめる。
   - スキーマを変えるときは、`SCHEMA_VERSION` を上げ、`migrate` に変換を足す。Supabase のテーブルは変えない。
- IndexedDB のデータベースのバージョンは 4。3 から上げるときは、アレンジのストアを足すだけで、既存のデータは消さない(ストアの構成を変えないかぎり、スキーマを変えても上げなくてよい)。

### データの流れ

1. 画面が `actions.js` の操作を呼ぶ。
2. 操作は repository から読み、`domain/` の関数で保存すべきレコードを計算し、保存して `notify()` する。
3. 各画面は `subscribe()` で通知を受け、repository から読み直して全体を再描画する。フォーカスと入力中の値は `data-focus-key` を目印に引き継ぐ(`keepFocus`)。

操作は1つずつ順番に実行される(`serial`)。並行して走ると、後から保存した方が先の変更を消してしまうため。

### データモデル

```js
Project  { id, title, memo, dueDate, isTemplate, bpm, scales }   // dueDate は 'YYYY-MM-DD' または null。bpm と scales([{ bar, root: 0〜11, mode: 'major' | 'minor' }]。小節の順で、1小節目は必ずある)はプロジェクトだけ
Lane     { id, projectId, type: 'section' | 'global', name, order, collapsed }
Task     { id, projectId, laneId, title, memo, status: 'todo' | 'doing' | 'done', order, doneAt,
           startDate, endDate,                       // 実績。どちらも 'YYYY-MM-DD' または null
           references,                               // リファレンスの曲名(string[])
           clipId }                                  // 連動タスクなら元のクリップの id。ふつうは null
Track    { id, projectId, name, order,               // アレンジ画面のトラック(プロジェクトだけ)
           program, volume, pan, drum,               // GM の音色(0〜127)、音量・パン(0〜127。パンは64が中央)、ドラムか
           mute, solo }                              // ミュート・ソロ(再生だけに効く)
Clip     { id, projectId, trackId, name, memo, startBar, bars,   // 小節は1始まりの整数。bars は1以上
           notes: [{ pitch, start, length, velocity }] }        // 位置はクリップの先頭からの相対で、単位は tick(4分音符 = 480)
Marker   { id, projectId, laneId, bar }              // セクションマーカー。ボードのセクション(レーン)を指す
```

テンプレートは `isTemplate` が true の Project で、レーンとタスクの持ち方はプロジェクトと同じ(ステータス、締切、タスクの開始日・終了日を使わないだけ)。開始日・終了日を足す前に作ったタスクには、この2つの項目がない(なしとして扱う)。`references` も同じで、項目がなければなし(スキーマバージョンは上げていない)。Track の `mute` と `solo` も、項目がなければ false として扱う(同じくバージョンは上げていない)。テンプレート専用のデータはない。プロジェクトは、どのテンプレートから作ったかを覚えない。

アレンジ(Track / Clip / Marker)はプロジェクトだけが持ち、テンプレートとのコピーには含めない。Marker の名前と色は、指しているレーンのものを使う(レーンを消すとマーカーも消える)。Clip は、属するセクションのレーンに連動タスク(`clipId` を持つ Task)として出る。連動タスクの `laneId` は、どのセクションにも入っていない(無所属の)間だけ null になる。

すべてに `createdAt` と `updatedAt` が付く。`Lane.type === 'global'` が「全体」レーン。詳しい型は `js/store/repository.js` にある。

## これから(未着手)

- **「次やる」ビュー**:各レーンの未完了タスクの先頭と作業中のタスクを横断して一覧にする。使ってみて欲しくなったら追加する。
- **Supabase に乗り換える**(以前の、項目ごとに列を持つテーブルで作ってある場合):
   1. ローカル(IndexedDB)か古い Supabase から JSON をエクスポートしておく。
   2. SQL Editor で `supabase/drop.sql` を貼り付けて実行し、続けて `supabase/schema.sql` を貼り付けて実行する(古いテーブルのデータは消える)。
   3. ログイン → インポート。
- **GitHub Pages でのホスト**:GitHub にリポジトリを作って push し、Settings → Pages で `main` ブランチのルートを公開する。ビルドは不要。
- **速度と通信の改善**:Supabase では1操作あたりの通信回数が多い。読み直しを減らす(手元の状態を先に更新する)、オフライン時に書き込みをキューに貯めて再送する、など。
- **本物の認証**:複数人で使う、または公開キーを秘密にしたくない場合は、Supabase Auth と user_id 単位の RLS に切り替える。
- **工程タグ**:必要になったら、タスクに任意のタグを付けてフィルタできるようにする。
